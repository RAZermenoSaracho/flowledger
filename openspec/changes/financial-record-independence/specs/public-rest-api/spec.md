## MODIFIED Requirements

### Requirement: Transaction deletion
`DELETE /v1/transactions/:id` SHALL call the existing `deleteTransaction` service. It SHALL return 404 for another user's or missing id. It SHALL remove the caller's related notifications and the caller's transaction only; a linked shared expense in which another user has a financial stake SHALL be kept, detached, with its participants and settlement requests unchanged. Deleting a transfer SHALL remove the single transfer row. Deleting a transaction created by an approved settlement SHALL leave the settlement request and the other user's records in place with only the caller's transaction link cleared. A repeated delete SHALL return 404.

#### Scenario: Cross-user delete
- **WHEN** user A's write key deletes user B's transaction
- **THEN** the response is 404 and B's transaction exists

#### Scenario: Delete transfer
- **WHEN** a write key deletes a transfer
- **THEN** the response is 204 and the transfer no longer affects either account's balance

#### Scenario: Delete with shared expense
- **WHEN** a write key deletes a transaction that has a shared expense with an accepted participant and a settlement request
- **THEN** the response is 204, the transaction is gone, and the shared expense, participant and settlement request remain unchanged for the participant

#### Scenario: Delete settlement payment
- **WHEN** a write key deletes a transaction generated by an approved settlement
- **THEN** the response is 204, the settlement request still exists with status approved and the other user's link and transaction intact

#### Scenario: Repeat delete
- **WHEN** the same delete is sent twice
- **THEN** the second response is 404
